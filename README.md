# Targets

Приложение за рецепцията на фитнес зала. Разбива продажбите на малки цели за всяка смяна, показва бонуса на всеки колега и прави класация между тях. Има два сайта с обща база:

| Сайт | Адрес | За кого |
| --- | --- | --- |
| **Служители** | `https://zdravkozoriev.github.io/targets/` | колегите на рецепцията |
| **Мениджър** | `https://zdravkozoriev.github.io/targets/manager/` | само за мениджъра, с вход през Google |

## Какво може

**Сайтът за служители**
- **Смяна:** колегата си избира името (телефонът го запомня) и вижда целта за днешната си смяна, напр. „4 / 8“. Продажба се записва с едно докосване на продукта и на екрана излизат фойерверки. При изпълнена цел има голямо празнуване.
- **Обща смяна:** вижда се общата цел и напредъкът на всеки. С „Кой продаде?“ двама могат да записват от едно устройство.
- **Класация** и **график** (само за четене).
- Грешно записана продажба се отменя веднага или се изтрива до края на деня.

**Сайтът за мениджъра**
- **Днес:** всички днешни смени, напредъкът на всеки, оборот и бонуси, последните продажби.
- **Класация:** същата като при служителите.
- **График:** смени по седмици. Всяка смяна има вид (сутрешна, вечерна, дублажна или свой) и колеги. Може да се копира миналата седмица.
- **Отчет:** за текущия и миналия месец, по колеги (смени с изпълнена цел, %, бройки, оборот, бонус) и по продукти. Бутонът „Копирай за заплатите“ копира бонусите като текст.
- **Настройки:** продукти с цена, бонус в € за бройка и цел за всеки вид смяна; видове смени с часове; колеги; състезание с име, награда, период и критерий.

## Как работи

Обикновен HTML, CSS и JavaScript, без билд и без зависимости. Данните са във **Firebase Firestore**, а влизането е през **Firebase Authentication**:

- Служителите влизат автоматично и анонимно, без парола. Четат всичко, записват продажби и могат да трият своите до 12 часа след записа.
- Мениджърът влиза с Google. Достъп имат само имейлите, добавени в колекцията `managers`.
- Правилата за достъп са във [`firestore.rules`](firestore.rules).

| Колекция | Съдържание |
| --- | --- |
| `config/main` | продукти, колеги, видове смени, състезание |
| `shifts/<id>` | `{date, type, start, end, staff[]}` |
| `sales/<id>` | `{date, time, ts, staffId, productId, qty, price, bonus, shiftId, uid, createdAt}` |
| `managers/<имейл>` | празен документ: кой е мениджър |

Бонусът се записва в самата продажба, затова по-късна промяна на бонуса на продукт не променя старите записи.

Докато Firebase не е настроен, двата сайта работят в **демо режим** с примерни данни, които не се запазват.

```
index.html, app.js            сайтът за служители
manager/index.html, app.js    сайтът за мениджъра
shared/                       общ код: стил, връзка с базата, сметки, общи изгледи
shared/firebase-config.js     настройките на Firebase проекта (попълват се веднъж)
sw.js                         офлайн кеш за двата сайта
```

## Настройка на Firebase (еднократно, около 10 минути)

1. Отвори https://console.firebase.google.com → **Create a project** → име, напр. `targets`. Google Analytics не е нужен.
2. **Build → Firestore Database → Create database**. Избери локация `eur3 (europe-west)` и **production mode**.
3. В **Firestore → Rules** замени всичко със съдържанието на [`firestore.rules`](firestore.rules) и натисни **Publish**.
4. **Build → Authentication → Get started → Sign-in method** и включи:
   - **Anonymous**
   - **Google** (избери имейл за поддръжка)
5. **Authentication → Settings → Authorized domains → Add domain:** `zdravkozoriev.github.io`.
6. **Firestore → Data → Start collection:** име `managers`, Document ID = твоят Gmail адрес, без полета (или едно поле, напр. `name`). Повтори за всеки мениджър.
7. **Project settings (зъбното колело) → General → Your apps → Web (`</>`)** → регистрирай приложение. Копирай стойностите от `firebaseConfig` в [`shared/firebase-config.js`](shared/firebase-config.js) и качи промяната.

Тези стойности не са тайни и спокойно могат да са в публично хранилище. Данните пазят правилата от стъпка 3.

После отвори мениджърския сайт, влез с Google и в **Настройки** добави продуктите, колегите и целите. В **График** сложи смените.

## Публикуване (еднократно)

1. В GitHub: **Settings → Pages → Build and deployment → Source: GitHub Actions**.
2. Всяко качване в основния клон публикува двата сайта чрез `.github/workflows/pages.yml`. Ръчно: **Actions → Публикуване в GitHub Pages → Run workflow**.

> GitHub Pages за **частни** хранилища изисква платен план (GitHub Pro). В хранилището няма данни на колегите, те са само във Firebase, така че кодът може да е публичен.

## Инсталиране на телефона

- **iPhone (Safari):** отвори адреса → бутон „Сподели“ → „Добави към началния екран“.
- **Android (Chrome):** отвори адреса → менюто ⋮ → „Инсталирай приложението“ / „Добави към началния екран“.

Сайтът за служители и мениджърският се инсталират поотделно, всеки със своя икона. При слаб интернет продажбите се пазят на телефона и се изпращат, щом връзката се върне.

## Локално стартиране

```bash
python3 -m http.server 8000
# служители: http://localhost:8000
# мениджър:  http://localhost:8000/manager/
```

За вход с Google локално добави `localhost` в Authorized domains (обикновено е там по подразбиране).

## Стартиране на компютъра с Docker (Windows)

1. Инсталирай [Docker Desktop](https://www.docker.com/products/docker-desktop/) и го стартирай. Остави режима **Linux containers** (по подразбиране).
2. Изтегли кода: в GitHub натисни **Code → Download ZIP** и разархивирай (или `git clone`).
3. Отвори PowerShell в папката и изпълни:
   ```powershell
   docker compose up -d --build
   ```
4. Отвори http://localhost:8080 (служители) или http://localhost:8080/manager/ (мениджър).

Контейнерът тръгва автоматично заедно с Docker Desktop. След обновяване на кода изпълни отново `docker compose up -d --build`. Спиране: `docker compose down`. Данните са във Firebase, затова компютърът и телефоните виждат едно и също.

## Важно за сигурността

Анонимният вход означава, че всеки, който знае адреса на сайта за служители, може да го отвори и да запише продажба. Не разпространявай адреса извън екипа. Мениджърските действия (цели, бонуси, график, изтриване на чужди продажби) са защитени с Google вход и правилата във Firestore.
